# Project Rules

These rules apply to all UI work in this project. Follow them exactly.

## UI components

- **Always use shadcn/ui components** for every UI element (buttons, inputs, tables, dialogs, tabs, cards, badges, etc.).
- Add missing components with the shadcn CLI (`npx shadcn@latest add <component>`), not hand-written replacements or other component libraries.

## Theme

- **The theme cannot be changed.** Do not modify the shadcn theme: no edits to the CSS variables/design tokens in `app/globals.css`, no changes to the base color, radius or fonts, and no theme switching or re-theming.
- Do not hard-code colors or override component styling to get around the theme. Use the existing theme tokens (e.g. `bg-primary`, `text-muted-foreground`) only.

## Code style

- **Always use arrow functions** for components, helpers and handlers (`const Foo = () => { ... }`), not `function` declarations. Page and layout files use `const Page = () => { ... }` followed by `export default Page`.
- **Always style with Tailwind CSS classes** via `className`. No inline `style` props, CSS modules or hand-written CSS for components. Use `cn()` from `@/lib/utils` to combine conditional classes.
- Files generated by the shadcn CLI in `components/ui/` are left as generated; do not hand-convert them.
